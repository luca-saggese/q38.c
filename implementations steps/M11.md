# q38.c — Post-M10 Long-Context Roadmap

Proposed phase: **M11**

Target:
- Qwen3.8-Flash-Next full multimodal runtime;
- DGX Spark / GB10;
- selective Q4 target from M8;
- sessions/server/MTP from M9;
- multimodal path from M10;
- file-backed PLE from M4S.

Objective:
Extend the validated native context from 262,144 tokens toward:

```text
500k validated target
1M experimental target
```

without compromising the stable 262k target.

---

# 1. Milestone split

M11 should be divided into three explicit tracks:

```text
M11A — YaRN extended context to ~500k
M11B — FP8 QSA KV cache
M11C — 1M experimental context
```

Do not attempt 1M directly.

---

# 2. Baseline facts and assumptions

Native model context:

```text
262,144 tokens
```

Long-context growth is dominated mainly by QSA-related state because:

```text
GDN recurrent state       fixed size
GDN conv history          fixed size
PLE token history         fixed size
PLE table                 file-backed
GR                         transient activation
QSA main KV               grows with context
QSA index/compressed data grows with context
QSA pending/raw state     small/bounded relative to KV
```

This makes QSA KV compression/precision the primary memory lever for 500k–1M.

---

# 3. M11A — YaRN extended context to 500k

## 3.1 Goal

Validate increasingly long contexts while keeping QSA KV at the stable pre-M11 precision.

Suggested sequence:

```text
262,144 native baseline
320k
400k
500k
```

Do not mark 500k supported until quality and state correctness are validated.

## 3.2 YaRN configuration

Freeze the exact extended-context parameters from the selected reference implementation.

A likely candidate based on known Qwen3.8 experiments is conceptually:

```text
rope scaling type = yarn
factor             = 4
original max pos   = 262144
```

but **do not hardcode these values solely from external experiments**.

Verify against:
- Qwen documentation;
- Transformers support;
- llama.cpp/Qwen4Exp implementation;
- empirical quality.

## 3.3 Required implementation

Add a dedicated configuration structure:

```c
typedef struct {
    bool enabled;
    float factor;
    uint32_t original_max_position_embeddings;
    ...
} q38_yarn_config;
```

RoPE/QSA code must support:

```text
native mode
extended YaRN mode
```

without changing compiled model weights.

## 3.4 Correctness tests

Test position ranges:

```text
0
1
262143
262144
300k
400k
500k
```

Compare:
- position IDs;
- rotary frequencies;
- Q/K post-RoPE;
- QSA selected IDs for reference cases.

## 3.5 Quality tests

Use at least:

### Needle-in-a-haystack

Place needles at:
- 10%;
- 25%;
- 50%;
- 75%;
- 90%.

Test contexts:
- 262k;
- 320k;
- 400k;
- 500k.

### Long-range key retrieval

Multiple keys distributed across context.

### Long-document QA

Use a deterministic synthetic/document corpus.

### Logit/perplexity drift

Measure relative to native-context behavior on overlapping lengths.

## 3.6 Memory tests

Measure:

```text
bytes/token QSA K
bytes/token QSA V
bytes/token index state
total persistent state
workspace peak
PLE resident/cache bytes
OS headroom
```

Derive the real slope:

```text
MiB per 1k tokens
```

Do not infer 1M feasibility from theoretical dtype sizes alone.

# 4. M11B — FP8 QSA KV

## 4.1 Goal

Reduce the memory footprint of the growing QSA KV state enough to make ~1M context feasible on one Spark.

Do **not** quantize all recurrent state indiscriminately.

Primary target:

```text
QSA K
QSA V
```

Candidate format:

```text
FP8 E4M3
```

or the exact format proven best on GB10.

## 4.2 Do not quantize by default

Keep at stable precision unless separately validated:

```text
GDN recurrent state
GDN conv history
router
QSA index scores/state if sensitive
norm parameters
```

## 4.3 KV scaling policy

Freeze and document:

```text
per tensor?
per head?
per block?
per token block?
static/dynamic scale?
```

Do not implement FP8 storage without an explicit scale model.

## 4.4 Reference path

Maintain:

```text
BF16/FP16 QSA KV
```

as the semantic baseline.

FP8 acceptance requires:

```text
same selected QSA positions where expected
bounded attention-output error
bounded downstream logit drift
stable long-context retrieval
```

## 4.5 Test matrix

At minimum:

```text
1k
4k
16k
64k
262k
400k
500k
```

Compare:

```text
BF16 KV
vs
FP8 KV
```

Metrics:
- selected IDs;
- attention output;
- logits;
- greedy continuation;
- retrieval quality;
- memory;
- throughput.

---

# 5. FP8 path must be chunk invariant

FP8 KV scaling must not create chunk-dependent results.

Run:

```text
same token stream
```

with:

```text
single prefill
small chunks
large chunks
random partitions
```

Compare:

```text
stored FP8 KV bytes/scales where deterministic
dequantized KV
QSA selected IDs
attention output
final logits
```

If dynamic scaling depends on chunk shape, the scaling algorithm must be redesigned.

# 6. M11C — 1M experimental context

M11C starts only after:

```text
M11A 500k PASS
M11B FP8 KV PASS
```

## 6.1 Initial targets

Increase gradually:

```text
600k
750k
900k
1,000,000
```

Do not jump directly from 500k to 1M.

## 6.2 Hard memory gate

Before each context length, memory planner must predict:

```text
model resident bytes
PLE cache/staging
QSA KV bytes
QSA index bytes
GDN state
workspace
OS reserve
CUDA runtime reserve
```

Abort the test before allocation if predicted headroom is unsafe.

## 6.3 Suggested safety margin

For experimental 1M tests, preserve a minimum operational reserve.

Do not intentionally run at effectively 128/128 GB resident pressure.

Exact reserve should be calibrated from M7/M8/M10 measured behavior.

---

# 7. 1M quality gate

Do not call 1M “supported” because a prompt allocates successfully.

Required:

```text
allocation success
+
prefill completes
+
decode completes
+
retrieval quality acceptable
+
no state corruption
+
repeatability
```

## Required evaluations

### Needle tests

Needles near:
- beginning;
- quarter;
- middle;
- three quarters;
- end.

### Multi-needle

Multiple keys requiring discrimination.

### Position stress

Questions depending on:
- very early context;
- >500k region;
- >900k region.

### Multi-turn continuation

Extend a session incrementally rather than one monolithic prompt.

---

# 8. Prefix/session caching under long context

By M11 the runtime will have M9 session/checkpoint support.

Do not use a single generic cache block concept for all state.

Separate:

```text
GDN checkpoint interval
QSA main KV allocation granularity
QSA compressed/index block granularity
QSA pending/raw ring
PLE conv/history state
```

Checkpoint restore must reconstruct the exact semantic state.

## Test

For a long context:

```text
live run to N
```

must equal:

```text
restore checkpoint K
+
replay K..N
```

for:
- QSA state;
- GDN state;
- logits;
- greedy continuation.

---

# 9. MTP interaction with long context

If MTP was enabled in M9:

- speculative decoding remains optional;
- 1M support must first work with vanilla target decode.

Only then validate MTP.

## QSA pending ring

MTP can increase the number of uncommitted/pending tokens that must be represented by the QSA raw group state.

The pending-ring capacity must be derived from:
- compression ratio;
- number of speculative tokens;
- exact frozen QSA semantics.

Do not retain a capacity hardcoded for non-speculative decode.

## Losslessness gate

At every tested context length:

```text
vanilla greedy Q4
==
MTP speculative greedy Q4
```

exact token sequence.

If not, MTP remains disabled for extended context.

---

# 10. Multimodal long context

M10 adds image/video.

M11 must test multimodal context separately because visual tokens consume context budget and may affect multimodal position handling.

Test:

```text
long text + one image
long text + multiple images
long text + video
image near beginning, question near end
image near middle
multiple image references across >262k text tokens
```

Validate:
- multimodal position IDs;
- mRoPE;
- QSA selected positions;
- no integer overflow;
- no position-wrap bugs.

Do not claim multimodal 500k/1M support based only on text-only tests.

---

# 11. PLE behavior at very long context

PLE itself is fixed-storage/file-backed, but access behavior may change during very long prompts.

Measure:

```text
unique rows / 1k tokens
cache hit rate vs context length
NVMe bytes read
page-fault rate
prefetch efficiency
cache pollution
```

Do not assume cache hit rate stays constant from 16k to 1M.

If locality collapses, prefer:
- smaller cache;
- better read coalescing;
- async staging;

over increasing cache size.

---

# 12. Q4 / FP8 mixed precision experiments

M8 established selective Q4.

M11 may add controlled FP8 experiments for side/core weights if useful for memory/performance.

Candidate ablations:

```text
routed experts        Q4
PLE                   Q2/Q4 selected M8 recipe
shared expert         Q8/FP8 experiment
GDN projections       Q8/FP8 experiment
QSA projections       Q8/FP8 experiment
router                keep high precision
GDN recurrent state   keep FP32 initially
QSA KV                FP8 in M11B
```

Do not reduce target-model precision solely to force 1M fit unless the quality delta is explicitly accepted.

---

# 13. GB10-specific kernel tuning for long context

At long contexts QSA behavior may shift toward:
- larger gather sets;
- larger cache footprint;
- more memory pressure.

Re-profile:

```text
indexer
exact top-k
gather
attention
KV append
FP8 quant/dequant
```

at:

```text
64k
262k
500k
1M candidate
```

Do not assume the optimal 4k kernel configuration remains optimal at 500k.

# 19. Stop conditions

Stop and investigate before proceeding if:

- QSA selected IDs change unexpectedly under FP8 due to implementation error;
- chunking changes FP8 KV representation/semantics;
- GDN state becomes context-length dependent unexpectedly;
- 500k quality is materially degraded by the selected YaRN configuration;
- memory growth exceeds the measured linear model;
- 1M requires unsafe memory pressure;
- multimodal position IDs diverge at extended positions;
- MTP changes greedy target output.

---

# 20. Final objective

The long-context roadmap should end with a runtime that can truthfully claim:

```text
native:
  262k

validated extended:
  ~500k

experimental:
  up to 1M with FP8 QSA KV
```

on a single DGX Spark, while preserving:
- selective Q4 model quality;
- file-backed PLE;
- deterministic exact QSA selection;
- session correctness;
- multimodal correctness;
- optional lossless MTP.
